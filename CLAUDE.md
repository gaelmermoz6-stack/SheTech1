## Project Overview

SheTech is a French-language e-learning platform targeting African women and girls. It is a monorepo of two independent apps:

- `shetechback/` — Node.js/Express REST API (ESM, Prisma + PostgreSQL, port 5000)
- `shetechfront/` — React 19 SPA built with Vite (React Router v7, port 5173)

The backend was migrated from a MySQL monolith to a modular Prisma/PostgreSQL (Neon) architecture; the frontend was migrated from state-based routing to React Router. Older docs or comments referencing MySQL, a single `server.js`, or "no React Router" are stale.

## Commands

### Backend (`shetechback/`)
```bash
npm run dev          # nodemon src/server.js (auto-reload)
npm start            # node src/server.js
npm run db:migrate   # prisma migrate dev — apply/create migrations
npm run db:generate  # prisma generate — regenerate client after schema edits
npm run db:studio    # prisma studio — browse the DB
npm run db:seed      # node prisma/seed.js
```
After any edit to `prisma/schema.prisma`, run `db:generate` (and `db:migrate` to change the DB).

### Frontend (`shetechfront/`)
```bash
npm run dev      # Vite dev server (host 0.0.0.0)
npm run build    # production build to dist/
npm run lint     # ESLint
npm run preview  # preview production build
```

There is no automated test suite in either app.

## Environment

Backend reads `shetechback/.env` (see `.env.example`). Required:
- `DATABASE_URL` — PostgreSQL connection string (Neon). **This is the only DB config**; there are no `DB_HOST`/`DB_USER`/etc. vars anymore.
- `JWT_SECRET` — signs auth tokens
- `PORT` — defaults to 5000
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — a default admin is auto-created on startup if no admin exists (`src/lib/startup.js`)
- `GMAIL_USER`, `GMAIL_PASS` — nodemailer (Gmail app password) for password-reset emails
- `OPENROUTER_API_KEY` — AI quiz generation
- `YOUTUBE_API_KEY`, `FRONTEND_URL` (reset-email links, default `http://localhost:5173`)

Frontend uses `VITE_API_URL` (defaults to `http://localhost:5000`).

## Backend architecture (`shetechback/src/`)

Layered structure: `server.js` → `routes/*.routes.js` → `controllers/*.controller.js` → Prisma. Shared helpers in `lib/`, middleware in `middlewares/`.

**Route mounting is uneven — check `src/server.js` before assuming a path prefix.** Only three routers are mounted under a prefix:
```js
app.use('/formations', formationRoutes);
app.use('/modules',    moduleRoutes);
app.use('/lecons',     leconRoutes);
```
All others (`authRoutes`, `progressionRoutes`, `projetRoutes`, `sessionRoutes`, `communityRoutes`, `marketplaceRoutes`, `certificatRoutes`) are mounted at root — those route files declare their **full** paths internally.

**Prisma client:** import the singleton `prisma` from `src/lib/prisma.js` (never `new PrismaClient()` in a controller). It memoizes on `global` to survive dev hot-reloads.

**Auth middleware** (`src/middlewares/auth.middleware.js`), applied per-route in the route files:
- `verifierToken` — validates `Authorization: Bearer <token>`, sets `req.user`
- `verifierAdmin` — requires `req.user.role === 'admin'`
- `verifierMentorOuAdmin` — requires `admin` or `mentor`

**User roles:** `apprenante` (default), `mentor`, `admin`.

**File uploads** (`src/middlewares/upload.middleware.js`): multer disk storage → `uploads/livrables/`, ≤5MB, whitelist of PDF/DOC(X)/JPEG/PNG/TXT. Uploads are served statically from `/uploads`. The `uploads/` tree is gitignored and recreated on startup by `server.js`.

**Domain-specific behavior worth knowing:**
- **Module quizzes** (`module.controller.js`): generated by calling OpenRouter (`model: 'openrouter/auto'`) and stored in `ModuleQuiz`. Submissions score `>= 70%` to pass; results are upserted into `ModuleQuizResultat` (composite PK `[userId, moduleId]`).
- **Certificates** (`certificat.controller.js`, `lib/pdf.js`): PDFs generated server-side with pdfkit, written to `uploads/certificats/`. Eligibility depends on module-quiz completion; each cert has a `codeVerification` and is unique per `[userId, formationId]`.
- **Progress**: `LeconFaite` (completed lessons) + `Progression` (per-formation percentage, composite PK `[userId, formationId]`).
- **Projets**: user submissions against admin-authored `ProjetBrief`s; mentors/admins evaluate (`statutEvaluation`, `note`, `commentaireMentor`).

## Frontend architecture (`shetechfront/src/`)

**React Router v7** with `createBrowserRouter` in `router.jsx` (rendered by `main.jsx`). Routes:
- Public: `/`, `/login`, `/register`, `/forgot-password`, `/reset-password`
- `/dashboard/*` — wrapped in `<ProtectedRoute>` + `<DashboardLayout>` (renders sidebar + `<Outlet>`); children: index (`DashboardHome`), `formations`, `projets`, `communaute`, `certificats`
- `/admin` — wrapped in `<AdminRoute>` (redirects non-admins to `/dashboard`)
- `*` → redirect to `/`

**Auth state** lives in `contexts/AuthContext.jsx` (`useAuth()` → `{ user, login, logout }`), persisted to `localStorage` (`token`, `user`). `ProtectedRoute`/`AdminRoute` (`src/components/`) gate on it.

**API calls:** import the shared axios instance from `src/lib/api.js`. Its request interceptor auto-attaches the Bearer token — do not set the header manually and do not re-create axios instances.

**Known inconsistencies (legacy from the pre-router version, still present):**
- `App.jsx`, `Dashboard.jsx`, and `MentorasPage.jsx` are **orphaned** — not referenced by `router.jsx`/`main.jsx`. Real routing goes through `router.jsx`; edit the routed components (`pages/*`, `layouts/DashboardLayout.jsx`, `Formations.jsx`, etc.), not these.
- Some components (`MentorasPage.jsx`, `Admin.jsx`, and the orphaned `App.jsx`/`Dashboard.jsx`) still declare a local `const API`/axios instead of importing `lib/api.js`. New code should use `lib/api.js`.
- `Admin.jsx` is still imported and used by `AdminDashboard.jsx`.

### Styling
- `App.css` is the primary stylesheet (global reset, CSS variables, `.dash-*` classes, auth/homepage). Imported in `main.jsx`. `Dashboard.css` is orphaned — do not use it.
- Sub-page components (`Formations.jsx`, `Community.jsx`, `Certificats.jsx`, `FormationDetail.jsx`, `MentorasPage.jsx`) bypass CSS variables and use hardcoded inline styles with a module-level `const ACCENT = "#C45C7A"`. `AdminDashboard.jsx` uses a `const C = {...}` palette object.
- Canonical accent is `#C45C7A` (rose/bordeaux); page background beige `#F9F0F3`; dark text/heading burgundy `#6D2E46`; secondary gold `#E8A554`.

## Database

PostgreSQL via Prisma. The single source of truth is `prisma/schema.prisma`; migrations live in `prisma/migrations/`. Models use `@@map`/`@map` to keep **snake_case table and column names** while exposing camelCase in code (e.g. `motDePasse` ↔ `mot_de_passe`, model `User` ↔ table `users`). Several join/result tables use composite primary keys (`ModuleQuizResultat`, `Progression`) or unique composites — respect these when writing upserts.
